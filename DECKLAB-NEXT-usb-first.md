# Deck Lab USB-first: next steps (usb-first workstream)

Branch `decklab/usb-first`, based on `decklab/getmusic-plus`. Goal: the same rekordbox-prepared stick works at home on
Deck Lab and at the club on club players, with the same cues, grids and phrase information. The stick is the library;
Mixxx's database is a cache. All fixtures here are generated byte by byte (no exports, no audio, no personal paths).

## 1. Audit: what the rekordbox feature imported (before this branch)

Source: `src/library/rekordbox/rekordboxfeature.cpp`, Kaitai parsers in `lib/rekordbox-metadata/`.

| Data | Imported? | How |
|---|---|---|
| Device discovery | Yes | Folders under `/media/*`, `/media/$USER/*`, `/run/media/$USER/*` holding `PIONEER/rekordbox/export.pdb` (or `.PIONEER/...`). Sidebar shows the mount folder name. |
| Tracks, playlists, folders | Yes | `export.pdb` parsed into temporary `rekordbox_*` tables (dropped at start and exit). History playlists are not read. |
| Title, artist, album, genre, year, comment | Only for new rows | `getOrAddTrack()` keys the track by absolute path; PDB metadata is copied only when the file was not yet in the Mixxx library. |
| Key | Yes | PDB key text, normalised, set with source USER so Mixxx does not re-analyse it. |
| Track colour | Yes | PDB colour id via a fixed table (`kColorForIDRed = 0xF870900` has seven hex digits, probably a typo; not changed, needs checking against rekordbox). |
| Beat grid | Partly | `.DAT` PQTZ as a beat map, shifted by an MP3 decoder offset (mp3guessenc). **Only when an `.EXT` file exists**: an export without `.EXT` got no grid. |
| Hot cues | Yes | PCOB/PCO2 hot cue lists: slots A–H → 0–7, names and RGB colours from PCO2. **Hot loops lost their end** (imported as plain hot cues). |
| Memory cues | Yes | First memory cue (by time) becomes the main cue with its name and colour; the others and memory loops become hot cues after the highest hot cue slot. |
| Loops | Yes | Memory loops as Mixxx saved loops (hot cue slots). |
| Legacy vs extended cues | **Bug** | `.EXT` carries both PCOB and PCO2 lists. Both were read, so memory cues could be imported twice (the copy becoming an extra hot cue), and the main cue colour dereferenced an empty `optional` when the PCOB copy sorted first. |
| Phrases (PSSI) | No | Parsed by the generated code (mask included) but never used. |
| Waveforms (PWAV/PWV2–PWV7) | No | Parsed and discarded; Mixxx re-analyses every track on first load (`AnalyzerWaveform`). |
| Ratings, play counts, My Tags | No | Shown in the rekordbox table only. |
| Errors | **Unsafe** | Kaitai throws on malformed files; `readAnalyze` did not catch, so a damaged ANLZ file could terminate Mixxx. Kaitai also allocates whatever length a tag claims before reading it (`std::vector<char>(len)`), so one bad length could ask for gigabytes. |
| Writes to the stick | None | The feature only reads. (Mixxx's optional tag write-back would fail harmlessly on the read-only appliance mount.) |
| Re-import | Every load | `RekordboxPlaylistModel::getTrack()` re-applies grid, cues, key and colour each time a row is loaded, so the stick already wins for those fields, but a cue deleted on the stick stays in the Mixxx cache. |

## 2. What this branch implements

### rekordbox import fixes (`rekordboxfeature.cpp`, locked input, hash refreshed)
- ANLZ files are read whole (they are well under 1 MB; refused above 32 MB), their framing is checked
  (`rekordboxanlz.cpp: anlzFramingIsSane`: header and every tag inside the file) and parse errors are caught. A damaged
  file is skipped with a warning.
- The grid is read from `.DAT` also when there is no `.EXT`.
- Within one file, PCO2 lists win over PCOB lists (Deep Symmetry's beat-link does the same).
- Hot loops keep their end (`CueType::Loop`); an existing slot changes type when the stick's changed.
- No empty-`optional` dereference for the main cue colour.
- `/media/decklab/<FS-UUID>` is scanned for any appliance user name and the stick is listed under its filesystem label
  (from `/dev/disk/by-label`, falling back to the UUID; names stay unique because they are the device key).

### Phrase analysis
- **Parser.** The upstream `rekordbox_anlz.ksy` already had `song_structure_tag` (PSSI) with the rekordbox 6 XOR mask
  (19-byte base pattern plus the entry count, applied to every byte after `len_entries`). One fix, made consistently in the
  ksy and the generated `rekordbox_anlz.cpp`: masked detection is `raw_mood > 3` instead of `> 20`. The mask's first byte
  is `0xCB + count`, which wraps to zero at 53 phrases, so a masked mid-mood tag read `0x0014` (20) and stayed masked.
  Worth upstreaming to crate-digger.
- **Kaitai-free API.** `src/library/rekordbox/rekordboxanlz.{h,cpp}`: `extractAnlz()` (PQTZ beat times, PSSI) from an
  already parsed file, `parseAnlz()` from bytes (never throws), `readAnlzFile()` with the framing check.
- **Model.** `src/decklab/decklabphrase.{h,cpp}`:
  - names per mood as rekordbox labels them (high: Intro 1/2, Up 1/2/3, Down, Chorus 1/2, Outro 1/2 from k1/k2/k3; mid:
    Intro, Verse 1–6, Bridge, Chorus, Outro; low: three ids each for Verse 1 and 2), translated;
  - colours per mood after beat-link's rekordbox-like palette, with intros moved from red to rose so nothing reads as the
    live red (#FF3D2E is for the playhead only);
  - `buildPhraseMap()` places phrase beats on the exported PQTZ grid (beat n = grid entry n), with the same decoder offset
    as the imported grid. Unknown mood, a phrase outside the grid, phrases out of order or an empty grid give no map: it
    never guesses. The last phrase ends at `end_beat`, clamped to the grid;
  - `phrasePosition()`: current beat = last grid beat at or before the position; returns the phrase and whole beats to its
    end. `phraseCountdownText()` is club style "bars.beats" where beats run 4..1 (16 beats = "3.4", last beat = "0.1").
- **Lifetime.** The map rides on the `Track` object as a dynamic property (`setTrackPhrases`/`trackPhrases`), set by
  `RekordboxPlaylistModel::getTrack()`. It lasts exactly as long as that track object (loaded deck); nothing is written to
  the database. A track loaded from another view has no phrases until it is loaded from the stick again.

### Phrase display
- **Overview bands** (`src/decklab/decklabphraseview.{h,cpp}: DeckLabPhraseBands`): an 8 px child of the whole-track
  overview, along its bottom edge (1 px ground hairline + 7 px bands, 1 px gap closing each band, fill-ins lightened in the
  upper half, played part shaded, 2 px live-red playhead). Transparent to touches (needle search unchanged), opaque
  painting from a cached image, repaints only when the playhead moves to another pixel. Hidden without phrase data. It
  works on any overview widget, so `WOverview` and the waveform renderers are untouched.
- **Deck readout** (`decklabdeckwidgets.*`): `DeckLabStripState::phrase` (`DeckLabPhraseReadout`: name, countdown,
  colour). Full readout: the chip (14 px SemiBold uppercase label on the phrase colour) and an 18 px tabular countdown in a
  fixed cell replace the four-segment beat meter (whose room grows to fit "CHORUS 2"). Four-deck cards: lit lamps keep
  their place in the lamp row; the phrase takes what is left, eliding the name and, when even that does not fit, showing a
  colour swatch with the countdown. No phrase data, or a position outside every phrase: the readout is exactly as before.
- **Hooks in `wdecklab.*`** (decks-ui's file; three marked additive spots, `usb-first:` comments): `addOverview()` creates
  the bands and queues one refresh; `refreshDeck()` reads `trackPhrases()`; `fillDeckClock()` fills the readout and
  moves the bands' playhead from the position and duration it already reads (no new timers or control watchers).

## 3. rekordbox 3-band waveform (PWV6/PWV7): assessed, not implemented

Facts (Deep Symmetry's analysis docs): PWV6 (`.2EX`) is the whole-track preview, 1200 columns of 3 bytes in the order
mid, high, low; club players draw the bands stacked (low dark blue, mid amber, high white). PWV7 is the scrolling detail at
150 columns per second, same byte order, with a non-linear height scale nobody has matched yet. The generated parser reads
both tags (`wave_3band_preview_tag`, `wave_3band_scroll_tag`; header sizes match the docs).

**Data mapping is clean; integration is not contained**, so it is not behind a setting yet:
1. `AnalyzerWaveform::shouldAnalyze()` re-runs whenever the main waveform is missing, which is always the case for a
   fresh stick track, and `initialize()` then replaces both the main waveform and the summary on the track and stores its own
   summary in the database. A summary set from PWV6 would be overwritten seconds later. Needs an "external summary,
   analyse the main waveform only" path in `src/analyzer/` (unowned) plus a waveform version tag so the cached Mixxx summary
   does not win on the next load.
2. Looking like the club needs the stacked low/mid/high drawing: a new overview render mode in `woverview`/the overview
   renderers (perf-engine/pi4-perf own them). Mixxx's RGB/LMH modes would show the same envelope in different colours.
3. Scale: Mixxx summaries are 0–255 peak magnitudes normalised per track; PWV6 heights use rekordbox's own scale.
   Matching needs a reference stick and side-by-side captures.
4. PWV7 for the scrolling waveform would replace analysis for the main waveform too (441 Hz visual rate vs 150/s), again in
   renderer and analyzer code owned elsewhere.

Proposed path: (a) analyzer flag + `Waveform::fromRekordboxPreview(1200x{mid,high,low})` resampled to the summary size
with `all = max(bands)`; (b) a `[DeckLab] RekordboxWaveforms` setting (default on for rekordbox sources) read by the
analyzer; (c) a stacked overview mode by the renderer owners. Skipping waveform analysis for stick tracks would also save Pi
CPU on every first load.

## 4. USB-first data model

### Problem
Mixxx keys tracks by absolute path (`track_locations.location`). Cues, loops, analysis, play counts, crates and playlists
hang off `library.id`, which hangs off that path. The appliance now mounts at stable `/media/decklab/<FS-UUID>`, but
existing rows use `/media/<user>/<label>/` (udisks: label, or the UUID when unlabeled). A stick that comes back under a
new path looks like new files: new rows, empty cache, history split.

### Identity
A stick track's identity is **(filesystem UUID, path relative to the filesystem root)**. The UUID survives relabelling
and remounting; the relative path is what rekordbox writes in the PDB (`/Contents/...`). Rows written before the appliance
mount scheme carry only a label (or a UUID) in their path, so the label is the evidence for those, double-checked by file
size.

### Safe first step (implemented): relink on mount
`src/decklab/decklabusbrelink.{h,cpp}`, hooked in `MixxxMainWindow` to `DeckLabSystem::usbChanged` (decklabd
`usb.list`/`usb.changed`: `id` = FS UUID, `label`, `mount`).
- For each drive: library rows under an earlier mount of that stick (`/media/<user>/<label|uuid>/…`,
  `/run/media/<user>/<label|uuid>/…`, `/media/<label|uuid>/…`; never the current mount or a folder containing it) are
  candidates. A row moves to `<mount>/<same relative path>` only if the old path no longer answers, the new path is a
  regular file, and its size equals the recorded `filesize` (when one is recorded).
- `track_locations.location/directory/filename` are updated in one transaction (`fs_deleted = 0`), each `WHERE id AND
  location = old`. A row already at the new path (loaded from the stick before) is reported and both rows are kept. Rows
  are never deleted. Tracks in the global track cache (loaded, previewed) are left and retried on the next drive event.
- File checks are `stat()` on a QtConcurrent worker; the database work is on the GUI thread; the stick is never written.
  Library views refresh through `TrackDAO::slotDatabaseTracksRelocated`, as after a folder relink.
- Each (UUID, mount) is handled once per session unless tracks were in use.

Limits: label-based old rows are ambiguous when two sticks share a label and a relative path with equal sizes (then they
hold the same file, which is acceptable). The library's root folders (`directories` table) are not moved yet. Rows created
at the new path while the stick was away remain separate.

### Proposal: the stick wins, the database caches
1. **Record identity on first sight.** Add `track_locations.fs_uuid` and `rel_path` (or a side table
   `decklab_volume_tracks(location_id, fs_uuid, rel_path)`) filled whenever a track under a decklabd mount is added. Relink
   then becomes exact (UUID + relative path, no label heuristics) and a stick can be recognised in any mount root.
2. **Merge duplicates.** When a relinked row conflicts with a row already at the new path, merge into the older `library.id`
   (cues from the stick, Mixxx-only data such as play counts, crates and history from both), then hide the newer row. This
   is the only step that removes a row and needs its own review.
3. **Cues and grid from the stick win** for rekordbox tracks: on every load (already the case for present cues). Add: cues
   that exist in Mixxx but not on the stick are removed only if they were imported from it (mark imported cues with a
   source flag), never cues the DJ made in Deck Lab. Phrases and PWV6 stay in memory (or a cache keyed by UUID + relative
   path + the ANLZ file's size/mtime).
4. **Playlists from the stick win.** Show the stick's playlists live from `export.pdb` (as now); never copy them into
   Mixxx playlists implicitly. An explicit "Copy to Deck Lab" can snapshot them. History made on Deck Lab stays in Mixxx.
5. **Never write to the stick** from the import path. If writing (prepared cues, recordings) is ever offered, it goes
   through decklabd `usb.set_writable` and rekordbox's own format, which is out of scope here.
6. **Root folders.** Move a `directories` entry the same way when its old root disappears and the new mount holds the same
   relative tree; otherwise leave the user's library folders alone.

## 8. Round 7 (r7-library): one entry per song, only the sticks that are in

Supersedes the relink limits in section 4 (proposal steps 2 and 6 are now implemented, without deleting rows).

- **Earlier addresses of a stick** (`decklabusbrelink.*`): a link to its mount (the appliance's
  `/media/<user>/<label>`, whatever it is called), a folder named after its label or FS UUID (any case), alone or with
  udisks' number (`<label>1`), under `/media/<user>`, `/run/media/<user>` or `/media`. A named folder that holds
  another filesystem now is never this stick. Same song = same relative path and the same recorded file size; never
  title or artist.
- **Merge**: twins merge onto the row at the current address (or, without one, the oldest row moves there). Cues and
  loops the survivor lacks move (one per hot cue slot, one main/intro/outro, saved loops not twice), crate memberships
  are united, playlist/history/Auto DJ entries point at the survivor in place, play count = max, last played = latest,
  added = earliest, rating and colour filled in, grid and key from the row the DJ edited (locked BPM, user key), else
  the analysed one. The merged row is hidden (`mixxx_deleted=1`) with whatever the survivor already had: nothing is
  deleted. Rows at the current address marked missing whose file is back are found again; library folders at an
  earlier address follow the stick.
- **When**: start-up (sticks under `/media/decklab`, no decklabd needed), decklabd's drive list, and a mount seen in
  the media folders; only while no deck, sampler or preview plays (retried every 10 s otherwise) and no library scan
  runs; songs whose track
  is loaded or cached wait for the next time. One transaction, after `VACUUM INTO <db>.decklab-merge-<time>` (the
  newest two copies are kept). The log line `Deck Lab USB merge` gives the counts.
- **Sticks that are out** (`decklabmedia.*`): the location ids of rows under a media folder that is not in (no folder,
  an empty one, a dangling link) go into `temp.decklab_media_away`; Tracks, crates, playlists, history (Mixxx's and
  Deck Lab's), Missing tracks, search, Mixes, the crate/playlist counts and the home count leave them out. They come
  back when the stick is in. Nothing is written to the library file; the stick's folder stays in `directories`
  and Mixxx's scanner skips it while it is out. Table models select again by themselves on a change.
- **Prevention**: the rekordbox device scan lists `/media/decklab` first and skips links to a folder already listed,
  so the appliance's label link is no second device.
- Tests: `src/test/decklabusbmergetest.cpp` (`DeckLabUsbMergeTest`, `DeckLabUsbMergeDbTest`, `DeckLabMediaTest`,
  `DeckLabMediaDbTest`).
